# 竞衡 · 比赛评分系统

自有服务器部署的评委评分系统，React + Node.js 24 / Express + SQLite + SSE。仅评委评分，不含观众投票和外部系统接入。界面使用警察蓝与科技蓝，首页直接为现场大屏。

## 本地启动

```bash
npm ci
npm run setup
# 可选；只对空数据库创建演示赛事
npm run demo
npm run build
npm start
```

打开 [现场大屏](http://localhost:3001/) 或 [管理工作台](http://localhost:3001/admin)。`setup` 生成管理员密码和签名密钥，保存在被 Git 忽略的 `.env`；终端显示初始密码。开发热更新使用 `npm run dev`。

已有演示赛事会保留。进入赛事设置点击“归档并新建比赛”，即可将当前比赛完整归档、进入可配置的筹备状态；保留项目和评委名单，重置当前评分与奖项，原二维码失效，需重新打印。历史归档可在赛事设置下载。也可设置新的 `DB_PATH=./data/official.sqlite` 使用独立数据库。正式环境不要执行 `npm run demo`。部署步骤见 [DEPLOY.md](DEPLOY.md)。

## 已确认并实现的规则

| 项目 | 实现 |
|---|---|
| 比赛规模 | 筹备阶段设置 1–100 位评委、1–200 个项目、1–20 轮；自动补齐席位和项目，可在管理页编辑名单 |
| 计分 | 单一总分，0–100，最多两位小数；不拆分维度 |
| 极值处理 | 开关控制，默认对称去最高 / 最低分，可切换不对称数量；至少保留一份评分 |
| 多轮汇总 | 每轮按去分规则算均分，最终取所有轮次平均分，保持百分制 |
| 评分开放 | 每次仅一个项目进入准备 / 开放状态；收齐并封存后再开放下一项目 |
| 统一亮分 | 未收齐仅显示评委序号与提交状态；默认收齐后自动亮分，可在赛前改为主持人确认后亮分 |
| 亮分顺序 | 全部亮分 → 极值高亮 → 缩小、淡出与划线剔除 → 巨幅本轮最终得分 |
| 重评 | 单位评委、多选或整组重评；其他评分保留，重新收齐才再亮分 |
| 二维码 | 每位评委独立凭证，有效期 48 小时；批量打印、停用、换码续期；不增加二次验证 |
| 奖项 | 一、二、三等奖固定名额；同分由管理员按赛事同分规则确认顺序，不自动扩额 |
| 展示入口 | 仅现场大屏；不提供独立公开查询门户，旧 `/ranking` 入口也显示当前大屏阶段 |
| 正式赛前测试 | 必须让全部评委至少完成一个测试项目；完成测试才能正式开赛；测试分不进入排名和成绩 CSV |

## 现场操作流程

1. 打开 `/admin/rules` 设置评委人数、项目数量、轮次、去分规则及固定奖项名额。奖项名额总和不能超过项目数量。
2. 在项目管理填写队伍、项目、出场顺序和队员名单；在评委管理核对席位并批量打印二维码。二维码有效期从创建或换码时起算 48 小时，测试和正式使用同一码。
3. 赛前补全团体获奖人员名单与独立个人奖。点击控制台“开始投屏演示”，进入 `/admin/present`；管理员在投屏前登录，按 **F** 全屏。演示画面没有常驻按钮或后台导航。
4. **单击画面、空格、右方向键或 PageDown** 都推进同一个下一步：开始测试（首队准备）→ 开始评分 → 全部提交后自动亮分 → 完成测试 → 进入正式比赛（首队准备）→ 开始评分。支持发送方向键 / PageDown 的翻页笔。
5. 正式比赛同样逐队推进：当前队全部亮分和动效结束后，下一步自动封存并切换下一队准备，再下一步开放评分。未收齐或亮分动画未结束时，点击和翻页均不会跳过。快速连按和同一状态重复请求不会连续误推进。
6. 亮分先展示全部原始分 1.5 秒，再高亮最高 / 最低分 1.6 秒，执行剔除动效，约 4.3 秒显示最终得分。未启用去分时 1.7 秒展示最终得分。按 **R** 可在当前画面打开重评，选择一人、多人或全部评委；重新收齐前隐藏分数，原记录保留审计。
7. 本轮最后一队亮分后，下一步自动进入下一轮首队准备。最后一轮完成后，下一步发布并展示最终排名。精确同分时先在当前页面填写队伍顺序与裁定依据，再推进排名；系统仅调整同分顺序，固定奖项名额不扩张。
8. 排名 → 团体奖项 → 个人奖项，始终用相同的单击或翻页键推进。排名 / 个人每页 8 条，团体每页 3 队；先翻完当前名单，再进入下一阶段。演示模式不自动翻页，刷新和其他大屏同步恢复服务器保存的阶段与页码。
9. **左方向键 / PageUp** 回看排名及获奖页面；评分阶段不能倒退。**H** 打开快捷键说明，**Esc** 关闭弹层。正式开赛后计分规则与名单锁定，发布后成绩和奖项锁定。
10. 赛后在后台导出 CSV、审计 JSON，并执行 `npm run backup`。更改规模、计分规则或参赛名单后，必须重新测试。传统后台控制入口仍可用于赛前管理；独立只读 `/screen` 跟随演示进度，无管理员操作权限。

## 补充功能点

- 现场控制台新增赛前检查：名单、评委凭证、计分与奖项、全员测试；提供对应处理入口。
- 评委席状态区区分近期在线、连接待确认、尚未连接、凭证不可用与已提交。在线依据已认证的评委状态请求，45 秒内视为近期在线，控制台每 15 秒刷新；并非设备连接保证，换码后需重新连接。
- 筹备阶段在控制台选择“主持人确认后亮分”。收齐后，管理员点击“公布本队成绩”，或在投屏演示按下一步；公布前公共接口不返回任何单分或汇总结果。重评后必须再次公布；旧公布请求会被拒绝。
- 大屏控制支持比赛画面、开场候场、中场休息三种场景，候场提示最多 100 字；0–120 分钟倒计时可开始、暂停、继续和重置。画面、剩余时间及截止时刻存储在服务器，刷新或重启后恢复；到时停留，不自动翻页、不截止评分。
- 候场与休息仅覆盖画面，不改变队伍、评分状态和当前页；停止收分请使用“暂停比赛”。投屏中按 **B** 切换休息画面，按下一步返回原比赛画面，之后再次按下一步才推进赛程。
- 大屏控制页提供只读大屏入口及场景预览，支持电脑和手机操作；现场大屏继续保持无常驻操作按钮。

- 项目、评委和队员名单管理；批量生成席位与项目。
- 测试与正式评分隔离，多轮数据保留，轮次和项目开放校验。
- 管理员 HttpOnly 会话；评委签名凭证、有效期、停用状态、比赛状态等服务端校验。
- 数据库唯一键为“测试 / 正式 × 轮次 × 项目 × 评委”；事务保障评分与审计一同落库。
- 相同分数重复请求幂等返回，冲突分数拒绝；重评版本号、赛程版本号阻止旧请求误提交。
- SQLite WAL 持久化、事务、外键、一致性在线备份；重启保留成绩、权限与登录会话。
- SSE 更新通知、心跳、断线重连、15 秒轮询兜底与回到前台时刷新。
- 手机端草稿按席位、阶段、轮次、赛程版本和重评版本隔离保存；恢复网络后由评委提交。
- 暂停 / 继续、收齐后封存、缺评提示、最终发布锁定。
- 服务器在未齐分时不向大屏接口返回单分、均分、总和、轮次明细或其他项目成绩；评委只收到自己的已提交分。
- CSV 导出正式各轮原始分、剔除标记、轮均分、最终平均分、排名与奖项；UTF-8 BOM，防公式注入。
- 重评保留原分值、原因、操作时间；完整审计可导出 JSON。
- 同源写入校验、登录失败限速、JSON 请求限制、CSP、生产 HTTPS Cookie。二维码凭证放在 URL fragment，进入后从地址栏移除。
- 手机适配、A4 打印、全屏、键盘操作、减少动效偏好支持。减少动效时保留亮分顺序，取消位移和缩放动画。

## 计算口径

每位评委总分以“百分之一分”整数存储。每轮齐分后按指定数量去掉极值，再取剩余评分的算术平均数；相同极值按评委 ID 稳定排序，仅去指定份数。最终分为全部轮次均分的平均值，不先将各轮均分舍入。由于赛中评委数与规则锁定，各轮保留份数相同，实现使用所有轮次保留分之和除以总保留份数，与各轮均分平均完全等价。

显示保留两位小数，排序比较未舍入的精确分数。显示相同的两位小数不一定精确同分。精确同分须按主办方既定规则由管理员确认顺序，固定名额不因同分扩张。名额可以设为 0。

停用评委不删除已有评分，也不减少应评人数；需要恢复或换码给该席位继续评分。项目出场序号由管理员维护，确认同分顺序时应保持序号唯一。

## 页面

| 地址 | 用途 |
|---|---|
| `/`、`/screen` | 现场大屏，只有管理员选定的当前展示内容 |
| `/admin` | 比赛控制台；准备、开始、封存、重评和核心管理入口 |
| `/admin/present` | 无常驻按钮的 PPT 式投屏演示；单击或翻页键推进，重评及同分确认无需离开画面 |
| `/admin/display` | 项目准备、开放、封存、展示阶段控制 |
| `/admin/rules` | 比赛规模、百分制、极值规则、固定名额 |
| `/admin/projects` | 队伍 / 项目 / 名单、重评 |
| `/admin/judges`、`/admin/print` | 席位、凭证、二维码批量打印 |
| `/admin/ranking` | 各轮平均分排名、同分顺序确认 |
| `/admin/awards` | 固定名额、团体队员与独立个人奖 |
| `/admin/logs` | 审计、CSV 与审计 JSON 导出 |
| `/judge#凭证` | 评委单一总分手机入口 |

大屏可直接打开以便投屏，不是独立的公开成绩浏览门户。未发布结果前，其他项目和最终排名不从大屏接口提供。

## 升级与部署边界

启动时自动迁移旧数据：添加 `entries` / `revisions`，将旧评分和重评版本复制到正式第一轮，保留原表及评委签名版本；添加队员名单和同分排序字段。迁移幂等。旧赛事已进行或结束时视为已完成赛前测试，避免阻断原赛事；旧的长有效期二维码首次升级会缩短为“原到期时间与升级后 48 小时中的较早者”。升级前备份，必要时重新打印有效期。

单服务器、单 Node 进程、单场赛事；SQLite 不直接用于多实例共享写入。配置上限并非吞吐量承诺，请按实际设备与网络规模演练。不接入短信、人脸或其他二次身份验证，二维码持有者即具有对应席位权限，可通过停用 / 换码处理。

源码结构：`server/` 为 API、存储、计算；`src/` 为三端界面；`scripts/` 为初始化、备份、演示；`tests/` 为计算、API、浏览器验证；`compose.yaml`、`Dockerfile`、`Caddyfile` 提供自托管部署。字体自托管，运行不依赖外部字体 CDN。


## 后台与大屏简化

后台首页直接提供当前队伍的准备 / 开始 / 封存与重评入口。大屏只显示“序号＋队伍名称”，不再重复展示项目小字；单轮不显示轮次，去分提示仅保留被剔除评分的状态。计分参数锁定时显示原因和归档新建入口，奖项名额使用独立保存接口，发布前可调整。

归档在同一个 SQLite 事务内保存当前规则、项目、评委、全部测试及正式分、奖项和审计，然后创建新的筹备状态。历史归档不进入当前排名，仅管理员可下载；它是比赛记录，不替代完整数据库备份。不提供从 JSON 一键恢复当前赛事的功能。


展示样式：评分大屏使用深蓝底白色巨幅得分；排名突出前三名并精简为名次、队伍、得分；团体奖以金银铜区分奖级，隐藏空等级，个人奖依据人数居中或分栏。多阶段亮分、管理员控屏及原有分页规则保持一致。
