# 拟真彩排手册：没有 20 台手机也能全流程验证

评委二维码的内容只是 `{PUBLIC_URL}/judge#{签名凭证}`，凭证本身可以通过管理端 API 获取
（`GET /api/admin/judges/test-links` 或 `GET /api/admin/judges/{id}/link`）。
因此**任何程序、任何浏览器标签页拿到这个 URL，就是"一位评委"**——不需要真机扫码。
本手册描述如何用"虚拟评委模拟器"在无真机条件下做全流程拟真测试。

## 三层测试法

| 层 | 手段 | 回答的问题 |
|---|---|---|
| L1 自动化回归 | `npm test` + `npm run test:e2e` | 代码逻辑对不对（含 30 席并发用例） |
| L2 人机结合彩排 | `npm run simulate`（纯评委模式）+ 你当主持人 | **现场流程顺不顺**——重点层，见下文 |
| L3 无人值守冒烟 | `npm run simulate -- --solo` | 整场比武从头到尾能不能自动走通，不变式是否全部成立 |

## 0. 环境隔离（务必先做）

彩排绝不能污染正式比赛库。用独立数据库 + 独立端口起一套彩排环境：

```bash
npm run setup                                   # 生成 .env（若还没有）
ADMIN_PASSWORD=彩排密码 TOKEN_SECRET=至少32位随机串 \
DB_PATH=./data/rehearsal.sqlite PORT=3005 PUBLIC_URL=http://localhost:3005 \
node server/index.js
```

注意 `--url` 必须与 `PUBLIC_URL` 同源，否则写请求会被来源校验拒绝（403）。
彩排后该库可整个删除；若在正式服务器上彩排，必须先「归档并新建比赛」。

## 1. 准备赛事数据

浏览器打开 `http://localhost:3005/admin`：

1. `/admin/rules`：设置评委数（建议与现场一致，如 20）、项目数、轮次、去分规则、奖项名额。
2. `/admin/projects`：把队伍、项目、出场顺序、队员名单填成**真实名单**（排版和翻页节奏才拟真）。
3. `/admin/judges`：核对席位；顺手点开批量打印页看二维码排版。
4. 想演练"主持人确认后亮分"，在 `/admin` 把成绩揭晓方式切到 manual。

验证模拟器能拿到凭证（不发送任何评分请求）：

```bash
npm run simulate -- --url http://localhost:3005 --dry-run
```

## 2. L2 人机结合彩排（核心）

一个终端跑虚拟评委，你用浏览器当主持人：

```bash
# 终端 A：20 位虚拟评委，测试评分阶段，10 倍速（30-90 秒思考延迟压缩到 3-9 秒）
npm run simulate -- --url http://localhost:3005 --kind test --speed 10
```

浏览器（最好双屏 / 或投屏到电视）：

- `/admin/present` 登录后按 **F** 全屏——你扮演主持人，用**翻页笔**推进全部流程；
- `/screen` 开第二个窗口——观察大屏动画与同步。

然后按真实比赛走：开始测试 → 逐队评分 → 亮分动画 → 重评 → 完成测试 → 正式比赛 → 多轮 → 发布 → 颁奖翻页。
虚拟评委会像真人一样错峰提交（每位有固定个人偏差，分数呈正态分布）。Ctrl+C 结束后输出报告。

**chaos 风格**（约 1/4 席位自动获得异常行为，适合演练应急处置）：

```bash
npm run simulate -- --url http://localhost:3005 --kind official --profile chaos --seed 7 --speed 10
```

- `double` 双击手：连点两次提交（验证幂等，报告应显示"幂等命中"）
- `stale` 旧页面手：用过期 epoch 提交（应 409 后自动重交）
- `late` 迟到手：拖到最后才交（管理台应出现缺评提示）
- `offline` 缺席手：全程不交——正好演练 **R 重评 / 暂停 / 补评** 的应急处置

`--seed` 固定后席位角色可复现；`--only 1,5` 可指定少数评委配合人工操作。

### 主持人检查清单（逐项打勾）

- [ ] 赛前检查页：名单、凭证、计分、全员测试四项通过
- [ ] 控制台评委席：虚拟评委显示"近期在线"（45 秒窗口），提交状态逐个点亮
- [ ] 测试评分：逐队推进流畅；未收齐时点按不跳过
- [ ] 亮分动画：全部原始分 → 极值高亮 → 剔除 → 巨幅得分，顺序与节奏正常
- [ ] manual 模式：收齐后公共接口无分数泄漏；按下一步才亮分
- [ ] 重评（R 键）：选 1 人 / 多人 / 全部；被重评席位旧页面提交被拒；分数隐藏→收齐→重新亮分
- [ ] 暂停比赛：暂停期间评委提交被拒；恢复后可继续
- [ ] 换码演练：给某席位"换码"，虚拟评委该席位应立即掉线（401），重新连接后退场
- [ ] 多轮：本轮最后一队封存后自动进入下一轮；轮次数据隔离
- [ ] 同分：若出现精确同分，页面要求先确认顺序；固定名额不扩张
- [ ] 发布：排名 → 团体奖项 → 个人奖项按页推进；左右方向键回看
- [ ] 大屏刷新：任意阶段刷新 `/screen`，画面恢复到当前阶段与页码
- [ ] 导出：CSV、审计 JSON 内容与实际一致；`npm run backup` 成功

## 2.5 测试阶段收官预演（内置功能）

测试评分阶段**全部队伍收齐**后，系统自动提供与正式发布完全一致的收官流程：

- 主持端（`/admin/present`）下一步依次变为：同分裁定（如有）→ 展示测试排名（预演）→
  团体奖项 → 个人奖项 → 完成测试；支持方向键回看，与正式发布操作完全相同
- 大屏画面左上角带**「测试预演」金色角标**，与正式发布画面一眼区分，可放心投屏演练
- 大屏控制页的「排名与颁奖」按钮在测试全齐后同步可用（标签显示 · 测试预演）
- 演练同分裁定：让虚拟评委对两队打相同分数（或人工控制），主持端会弹出裁定表单
- 完成测试后：正式排名、tie_order 全部归零，测试分留在隔离账；二维码不受影响

## 3. L3 无人值守冒烟（solo）

挂机自动跑完整场（测试评分 → 正式多轮 → 同分裁定 → 发布 → 导出校验），
**每一步都附带不变式断言**，任何一条失败立即停机：

```bash
npm run simulate -- --url http://localhost:3005 --solo --speed 30
# 专门触发同分确认流程：让出场位 2、3 的两队精确同分
npm run simulate -- --url http://localhost:3005 --solo --speed 30 --force-tie 2,3
```

内置不变式包括：未开放提交被拒、旧 epoch 被拒、重复提交幂等、
收齐未公布时公共接口不泄漏分数、未公布不能封存、未封存不能进下一轮、
同分未裁定不能发布、发布后排名完整、奖项名额不扩张、CSV 包含全部项目。
结束打印 `不变式断言: N/N 通过`；exit code 非 0 即有问题，按报告定位。

## 3.5 双机彩排布局（推荐）

两台电脑时按「前台 + 导演席」分工，观测面最全：

- **电脑 A（前台）**：浏览器打开大屏 `/screen`（接投影/电视），或坐主持人时开 `/admin/present` 按 F 全屏持翻页笔。
- **电脑 B（幕后）**：终端跑 `npm run simulate`（非 localhost 目标需 `--allow-remote`），
  浏览器开两个标签——`/admin` 看评委席在线/提交状态实时点亮，`/screen` 验证与主持人画面同步、刷新可恢复。

彩排服务跑在哪里，按二维码是否已发放二选一：

1. **码未发给评委 → 直接在正式服务器/正式库彩排**。B 直接
   `npm run simulate -- --url https://正式域名 --allow-remote ...`；全部演完后在
   赛事设置点「归档并新建比赛」回到筹备态（项目与评委名单保留）。注意：**归档会使全部二维码作废
   （token_version+1），必须重新打印/导出再发放**。
2. **码已发放 → 服务器上用同一镜像另起临时实例**：独立 `DB_PATH` + 独立端口，
   `PUBLIC_URL=http://服务器IP:彩排端口`（不设 NODE_ENV 时允许 http），
   正式库与已发二维码毫发无损。彩排结束立即删除容器/卷并关闭该端口。

A 电脑本地起服务亦可行（`PUBLIC_URL` 用 A 的局域网 IP、防火墙放行 Node）。

不必使用测试二维码：正式码天然可参加测试评分阶段（测试码只是可选的限制性凭证），
模拟器 `--kind official` 一条命令即可连续跟随测试与正式两个阶段、全程无需重启。
顺序口诀：**先彩排 → 再「归档并新建比赛」→ 最后发码**；归档会作废已生成的全部二维码。

建议剧本：
席位多配 1 个留给真手机（扫码混入验证真机路径）→
测试评分（`--kind test`，观察测试码自动退场）→ 正式比赛（`--profile chaos`，
演练双击幂等、旧页面 409、缺评卡死的应急：Ctrl+C 后 `--only 席位号` 单独补拉）→
R 重评 → 轮次切换与刷新恢复 → 发布颁奖 → 导出与终端报告。

## 4. 已知边界与实测发现

- **限流（429）**：全局 `/api` 限流 3000 次/分钟按 IP 计。反向代理部署时若未开
  `TRUST_PROXY=1`，所有评委设备共享同一个桶。真实人类节奏（20 席）远低于阈值，
  但彩排 `--speed` 超过 30 且评委很多时，SSE 扇出可能短暂触发 429——模拟器会自动退避，
  这本身也是对限流行为的验证。建议部署在反代后开启 `TRUST_PROXY=1`。
- **压力档**：`--profile stress` 全员同刻齐发，用于压 SSE 广播与 SQLite 写入；
  建议先跑 realistic 再跑 stress 对比 p95 延迟。
- **solo 与 chaos**：solo 下 `offline` 缺席手自动折算为 `late`（否则永远等不齐）；
  缺评→重评的完整处置请用 L2 人工演练。

## 5. 命令速查

```bash
npm run simulate -- --url http://localhost:3005 --dry-run        # 查看计划
npm run simulate -- -- --kind test    --speed 10                 # 测试阶段彩排
npm run simulate -- --kind official --speed 10                   # 正式阶段彩排
npm run simulate -- --kind official --profile chaos --seed 7     # 异常行为演练
npm run simulate -- --profile stress --count 100                 # 百席压测
npm run simulate -- --solo --speed 30 --force-tie 2,3            # 无人值守全流程
npm run simulate -- --help                                        # 全部选项
```

完全自动化的浏览器级拟真（30 独立评委会话 + 大屏 + 管理台）见 `tests/browser/thirty-judges.spec.js`，
由 `npm run test:e2e` 驱动，作为 L1 回归的一部分。
